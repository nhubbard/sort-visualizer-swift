# Functional contract matrix

Version: 2026-10-04. This is the Workstream 2 inventory for the supported iPadOS and Mac
Catalyst app. It maps observable outcomes to test owners and to the lanes in the
[source-verified coverage baseline](../../../Tools/TestCoverage/baselines/2026-10-02/README.md).
Paths below are relative to the repository root. A lane such as `catalyst/SortEngineKit` is a
key in `baseline.json`'s `results` object and either `verifiedTestResults` or
`behavioralOnlyResults`; `ios/ipad-ui`, `ios/app-intents`, and `catalyst/ui` name the three
app-facing bundles. The Catalyst UI bundle is
behavioral evidence but has no attributable line coverage in this Xcode run.

**Status:** Complete means the stated outcome has a positive and a meaningful edge or failure
assertion on every required platform. Partial means some evidence exists, but the named gap
still blocks using automation as the sole functional gate. Open means the required system or
host journey has no automated outcome assertion. A test that only proves a control or sheet
appears is marked partial. A module test on Catalyst proves shared logic, not iPad UI wiring.
Platform skips are not evidence for that platform.

This inventory has **35 contracts: 27 complete, 8 partial, and 0 open**. The coverage lanes
refer to the dated baseline; newer contract runs are listed in the relevant rows. The highest-value
next closure is a representative visualizer transition and geometry sweep (`VIS-01`). A Logic Pro
host capture closed `AUD-03`, and a live host disconnect plus rendered local PCM closed `AUD-02`.
The signed-in Mac/CloudKit canary closed `HIS-02`, and the
private-database size audit closed `HIS-04`.
These counts describe contract assertions, not source-line coverage.

## How to update this matrix

For each product change, add or revise a row at the observable outcome level. Name the production
owner, test file, required platform, and exact result-bundle lane. A row becomes complete only
when the positive and failure/edge outcome assertions pass in every required lane. If a feature
needs an external service or DAW, keep the scripted canary and its captured result separate from
simulator coverage. When tests move or are renamed, verify the file and test function against the
source and the current `.xcresult`, then regenerate the coverage baseline. See the
[coverage plan](coverage-plan.md) for gate thresholds and execution cadence. Run
`python3 Tools/TestCoverage/check_contract_matrix.py` from the repository root to catch stale
file links, duplicate IDs, missing status, and result-bundle lane references.
