Pigeonhole Sort is a sorting algorithm suited to inputs whose value range is close in size to the number of elements being sorted. Its name comes from the [pigeonhole principle](https://en.wikipedia.org/wiki/Pigeonhole_principle): rather than comparing elements against one another, it allocates one "pigeonhole" for every possible value in the input's range, drops each element into the hole matching its value, and then re-collects the holes in ascending order to produce the sorted output.

The algorithm works in two passes. First, it scans the input once to find the minimum and maximum values present, and allocates an array of holes sized to cover that entire range. It then makes a second pass over the input, incrementing the count in the hole corresponding to each element's value. Finally, it walks the holes from smallest to largest, and for each one writes that hole's value back into the output as many times as it was tallied. Because no comparisons between elements are ever made, Pigeonhole Sort is not bound by the same lower bound that constrains [comparison sorts](https://en.wikipedia.org/wiki/Comparison_sort).

Pigeonhole Sort is closely related to [Counting Sort](https://en.wikipedia.org/wiki/Counting_sort), and the two are often described together — both allocate one slot per possible value and run in `O(n + k)` time and space, where `n` is the number of elements and `k` is the size of the value range. The key difference lies in how the tallies are turned back into output. Counting Sort's classic formulation converts its tally into a cumulative (prefix-sum) table and scans the original input a second time, using each element's own position to look up its exact output slot — a technique that happens to preserve the relative order of equal elements. Pigeonhole Sort's classic formulation does not: once an element's value has been folded into its hole's count, nothing distinguishes that instance from any other element that shared the same value, so the holes are simply re-emitted in bulk without ever consulting the original input again.

Because of this, Pigeonhole Sort as classically formulated is not a [stable sort](https://en.wikipedia.org/wiki/Sorting_algorithm#Stability) — elements with equal values are not guaranteed to keep their original relative order in the output, since their original positions were discarded the moment they were tallied. This makes Pigeonhole Sort best suited to sorting bare values where stability doesn't matter, whereas Counting Sort (or a stability-preserving variant of Pigeonhole Sort that keeps a list per hole instead of a bare count) is the better choice when equal elements carry distinguishing payload that must survive the sort in its original order.
