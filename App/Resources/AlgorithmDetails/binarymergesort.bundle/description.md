Binary Merge Sort is a hybrid variant of [Merge Sort](https://en.wikipedia.org/wiki/Merge_sort), a [divide-and-conquer algorithm](https://en.wikipedia.org/wiki/Divide-and-conquer_algorithm) invented by [John von Neumann](https://en.wikipedia.org/wiki/John_von_Neumann) in 1945. Merge sort works by recursively splitting an array in half until each piece contains a single element, and then repeatedly merging pairs of sorted pieces back together until the whole array is sorted. Because the merge step always combines two runs in linear time and the array is halved at every level of recursion, merge sort runs in O(n log n) time in the best, average, and worst cases, making it considerably more predictable than comparison sorts like [Quick Sort](https://en.wikipedia.org/wiki/Quicksort) whose worst case degrades to O(n²).

The recursive splitting of a plain merge sort, however, is not free: each recursive call and each small merge carries overhead that outweighs its benefit once a subarray is small enough. Binary Merge Sort addresses this by switching strategies below a fixed size threshold. Once a subarray shrinks to the threshold or smaller, the algorithm abandons further splitting and merging and instead sorts that run directly with [Insertion Sort](https://en.wikipedia.org/wiki/Insertion_sort). Insertion sort has a worse [asymptotic runtime](https://en.wikipedia.org/wiki/Asymptotic_run_time) of O(n²), but for small n its low constant factor, and its lack of recursive-call and buffer-allocation overhead, make it faster in practice than continuing to recurse. Larger runs are still divided in half and combined with the standard merge step. This kind of hybridization is a well-established optimization: production sorting routines, including the introsort and Timsort-style implementations found in many standard libraries, commonly fall back to insertion sort for small partitions for exactly this reason.

Like ordinary merge sort, Binary Merge Sort is a [stable sort](https://en.wikipedia.org/wiki/Sorting_algorithm#Stability): the merge step always prefers the element from the left run when both compared elements are equal, so items with equal keys retain their original relative order. Because using a constant-size threshold for the insertion sort fallback does not change the number of recursive levels or merges asymptotically, Binary Merge Sort retains merge sort's O(n log n) time complexity in the best, average, and worst cases. It is also not an [in-place algorithm](https://en.wikipedia.org/wiki/In-place_algorithm): the merge step requires an auxiliary buffer proportional to the size of the run being merged, giving the algorithm O(n) space complexity.
