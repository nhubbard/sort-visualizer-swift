# Algorithm Content Pipeline

Generates the syntax-highlighted code samples the app displays (via
`Modules/DesignSystemKit/Sources/CodeAttributes.swift`'s Pygments-token-based markdown).
Originally `Tools/AlgorithmContentPipeline/`, preserved from `Legacy/Shared/Resources/` when the
rest of `Legacy/` was removed (Phase 11) — this was the only part of `Legacy/` still in active use,
and was later folded into `App/Resources/AlgorithmDetails/` so the pipeline and its output live in
one place.

## Layout

Each algorithm has exactly one folder, `<algorithm-id>/`, holding both the authoring source and
the finished content side by side:

- raw source, `<algorithm-id>.<ext>` for `ext` in `c cpp cs go java js kt py rb swift`
- `description.md`
- one `<lang>.md` per language, generated by `highlight.py`, named to match `CodeLanguage.all`'s
  ids (`py.md`, `js.md`, `go.md`, `java.md`, `c.md`, `cpp.md`, `cs.md`, `rb.md`, `kt.md`,
  `swift.md`) — `AlgorithmDetailContent` reads by language id.

`Project.swift`'s `copyFiles` phases (`Module.algorithmDetailCopyFiles`) ship only the `*.md`
files out of each folder — the raw source never reaches the app bundle. This needs one Copy Files
build phase *per algorithm* (rather than one phase for everything): Xcode's Copy Files phase
applies a single destination to every file it copies, so shipping `<algorithm-id>/<lang>.md`
nested under `AlgorithmDetails/<algorithm-id>/` in the app bundle means each algorithm's `.md`
files need their own phase with that algorithm's subpath. `algorithmDetailCopyFiles()` discovers
every subdirectory here except `template/` and generates one phase per algorithm automatically —
no manifest changes needed when adding a new algorithm.

Other root-level content, none of it shipped:

- `template/` — master template used by `scaffold.sh` to start a new algorithm folder.
- `highlight.py` — runs Pygments over each algorithm's raw source, writing `<algorithm-id>/<lang>.md`
  directly in the `^[text](code: 'Token.X')` syntax `CodeAttributes` parses. Add new algorithm
  names to its `algorithms` list before running.
- `test.py` — compiles/runs each algorithm's raw source per language and checks output against an
  expected sorted result, to verify correctness before highlighting. `python3 test.py [name]`
  (all algorithms if no name given). Needs the actual toolchains installed (clang, javac/java,
  kotlinc, python3, ruby, swiftc, node, go, csc/mono — whichever languages you're checking). Its
  `algorithms` list lags `highlight.py`'s (some newer algorithms were never backfilled here) —
  pre-existing drift, unrelated to this layout.
- `scaffold.sh <name>` — creates `<name>/` from `template/`.
- `.gitignore` — one shared copy of the build-artifact ignore rules `test.py` needs (compiled
  binaries, `.class` files, etc.), covering every algorithm folder underneath it.

## Usage

```sh
cd App/Resources/AlgorithmDetails
python3 -m venv .venv && source .venv/bin/activate
pip install pygments coloredlogs   # coloredlogs only needed for test.py
python3 highlight.py
```

`highlight.py` writes straight to `<algorithm-id>/<lang>.md` — there's no separate shipped folder
to copy into afterward.
