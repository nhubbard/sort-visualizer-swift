Fun Sort repeatedly applies binary search to an array that is not yet sorted. Each search returns a position, and the algorithm swaps the element into that position before searching again. Repetition eventually produces the sorted order even though the intermediate binary searches do not operate on fully sorted ranges.

Testing convergence by value alone fails when duplicate values are present. A search can return the position of another equal element even though the current element has not reached its final position.

This implementation compares a composite key consisting of the value and its original input position. The original position breaks ties, so a search returns index i as a fixed point only when it reaches that specific element. The same tie-breaking rule preserves the original relative order of equal values, making the implementation stable.

This puts Fun Sort among the exchange sorts, alongside other algorithms that make progress primarily by swapping pairs of elements into place rather than merging, partitioning, or selecting. Its complexity is unusual for something built on binary search: the best case, where the array is already sorted (or close to it) and every search immediately returns a fixed point, is O(n log n). But because each swap can require the search to be redone from scratch, and a single element can need many rounds of searching-and-swapping before it settles, the average and worst cases climb to O(n² log n), quadratic in the number of elements, with an extra logarithmic factor from the repeated binary searches themselves.
