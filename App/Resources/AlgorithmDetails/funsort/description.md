Fun Sort earns its name from a genuinely strange idea: repeatedly binary-search an array for where each element belongs, even though the array generally isn't sorted yet at the time you search it. A binary search only works correctly on sorted data, so running one against a partially-scrambled array produces a "wrong" answer in the sense that it isn't really the array's sorted position — but it's still *a* position, and swapping the element there and searching again, over and over, turns out to converge on a fully sorted array anyway. It's chaotic in the literal sense: every individual search is operating on bad assumptions, yet the repeated process as a whole still finds its way to the correct global order. That's the "chaos of unordered binary search" the algorithm is named for.

A naive way to decide when an element has "converged" — found its final resting place — is to check whether the value the binary search landed on equals the value being placed, rather than checking whether the search actually landed back on the same index it started from. On an array with no duplicate values those two checks happen to agree, so the shortcut looks correct. But the moment two elements share a value, the search can land on the *other* equal element's index, see a value match, and declare victory without the element actually being in its correct position — leaving large stretches of a duplicate-heavy array unsorted.

This implementation avoids that trap by comparing elements on a composite key: their value, and — only when values tie — their original position in the input. Two elements are now never fully equal under this key, so "the search returned index i" can only mean the search actually landed back on i itself; a same-valued neighbor can no longer be mistaken for it. Convergence becomes a real fixed point instead of a coincidence. As a side effect, the algorithm also becomes stable: since ties are always broken by original index, two elements that started with equal values can never swap past each other, so they keep their original relative order in the output.

This puts Fun Sort among the exchange sorts, alongside other algorithms that make progress primarily by swapping pairs of elements into place rather than merging, partitioning, or selecting. Its complexity is unusual for something built on binary search: the best case, where the array is already sorted (or close to it) and every search immediately returns a fixed point, is O(n log n). But because each swap can require the search to be redone from scratch, and a single element can need many rounds of searching-and-swapping before it settles, the average and worst cases climb to O(n² log n) — quadratic in the number of elements, with an extra logarithmic factor from the repeated binary searches themselves.
