In computer science, bozosort is a highly inefficient [sorting algorithm](https://en.wikipedia.org/wiki/Sorting_algorithm) based on the [generate and test](https://en.wikipedia.org/wiki/Generate_and_test) paradigm, closely related to [bogosort](https://en.wikipedia.org/wiki/Bogosort). Where bogosort tests whether the array is sorted and, if not, produces an entirely new [random permutation](https://en.wikipedia.org/wiki/Permutation) of the whole array, bozosort instead swaps just two randomly chosen elements on each iteration before checking again whether the array happens to be sorted. The two indices are chosen independently and uniformly at random, so it is possible — if unlikely — for a "swap" to pick the same position twice, effectively a no-op step.

Because each iteration only nudges the array with a single [transposition](https://en.wikipedia.org/wiki/Cyclic_permutation) rather than reshuffling it outright, bozosort explores the space of possible arrangements far more slowly than bogosort does. Getting from one permutation to another still requires wandering through the symmetric group one swap at a time, so bozosort tends to need many more iterations than bogosort to sort the same input, even though each individual iteration is cheaper. Like bogosort, it has no finite worst-case bound: an unlucky run could in principle continue swapping forever without ever landing on the sorted order.

Bozosort has no practical application. It is used solely for educational and comedic purposes, typically presented alongside bogosort as an example of a deliberately absurd algorithm — a demonstration of just how badly a "sorting algorithm" can perform while still being technically guaranteed (with probability 1) to terminate eventually.
