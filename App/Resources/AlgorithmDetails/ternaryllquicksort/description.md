*From Wikipedia, the free encyclopedia*

Three-way (or ternary) Quick Sort is a variant of [Quick Sort](https://en.wikipedia.org/wiki/Quicksort) that partitions the array into three contiguous regions on each pass instead of two: elements less than the pivot, elements equal to the pivot, and elements greater than the pivot. The classic two-way partition only distinguishes "less than" from "greater than or equal to" the pivot, so every element equal to the pivot value is repeatedly re-examined and re-swapped as the recursion descends into ever-smaller sub-arrays. Three-way partitioning instead gathers every element equal to the pivot into a single block during the current pass, excludes that block entirely from both recursive calls, and never touches those elements again for the remainder of the sort.

This refinement makes almost no difference on arrays of mostly distinct keys, but it is dramatically more efficient on inputs containing many duplicate or equal keys — running time degrades gracefully toward linear time as the number of distinct key values shrinks, rather than toward the quadratic worst case that plain two-way Quick Sort suffers when it repeatedly partitions around a value that appears many times. Splitting a sequence into three regions in a single pass is itself a well-known problem in computer science, popularized as the [Dutch national flag problem](https://en.wikipedia.org/wiki/Dutch_national_flag_problem) and attributed to [Edsger Dijkstra](https://en.wikipedia.org/wiki/Edsger_W._Dijkstra); three-way partitioning is the classic solution to it. Applying the idea to Quick Sort is often credited to [Jon Bentley](https://en.wikipedia.org/wiki/Jon_Bentley_(computer_scientist)) and [Douglas McIlroy](https://en.wikipedia.org/wiki/Douglas_McIlroy), whose 1993 paper "Engineering a Sort Function" described an efficient three-way partitioning scheme for practical use in library sort routines.

There is more than one way to implement three-way partitioning; the various schemes differ in how many pointers sweep the array and in which direction each pointer is repositioned during the scan, while all arrive at the same three-region result. This variant uses what is commonly called an **"LL" two-pointer scheme**, in which the boundaries of the "less than" and "equal to" regions are both tracked and advanced from the left as the scan proceeds. A sibling **"LR" scheme** instead tracks boundaries growing inward from the left and right ends of the array at the same time. Both are correct implementations of the same three-way partitioning idea; they differ only in pointer bookkeeping, not in the asymptotic behavior of the resulting sort.

As with ordinary Quick Sort, three-way Quick Sort is an in-place [divide-and-conquer algorithm](https://en.wikipedia.org/wiki/Divide-and-conquer_algorithm) and a comparison sort. It is not a [stable sort](https://en.wikipedia.org/wiki/Sorting_algorithm#Stability), since elements considered equal to a pivot can be reordered relative to one another as they are gathered together during partitioning.
