Shell Sort is an in-place comparison sort named after its inventor, [Donald Shell](https://en.wikipedia.org/wiki/Donald_Shell), who published it in 1959. It is a generalization of [Insertion Sort](https://en.wikipedia.org/wiki/Insertion_sort) that allows the exchange of items that are far apart. The idea is to arrange the list of elements so that, starting anywhere, taking every h'th element produces a sorted sublist — a technique that lets far-flung out-of-place elements travel toward their final position in large jumps rather than one slot at a time, before the algorithm finishes with an ordinary, now nearly-free, insertion sort.

A conventional implementation picks a sequence of decreasing gap values, ending in 1, and runs a gapped insertion sort for each gap in turn: elements exactly `gap` positions apart are compared and shifted past each other, exactly as in plain Insertion Sort but stepping by `gap` instead of by one. Because later, smaller-gap passes only need to fix up the disorder left by earlier, larger-gap passes, the final gap-1 pass — which is a full Insertion Sort — runs on an already mostly-ordered array and finishes quickly. Shell Sort is not a [stable sort](https://en.wikipedia.org/wiki/Sorting_algorithm#Stability), since a long-distance exchange can reorder equal elements relative to one another, but it sorts in place, needing no auxiliary array. Its running time is sensitive to the chosen gap sequence: the original sequence halving down from `n/2` degrades to `O(n^2)` in the worst case, while later sequences such as Hibbard's or Sedgewick's push the worst case down toward `O(n^(4/3))` or better.

This recursive variant builds its gap sequence on the fly instead of iterating over a precomputed table. Given a range and a starting gap `g`, it first recurses into three overlapping sub-problems covering the range at three different starting offsets — `start`, `start + g`, and `start + 2g` — each recursing again with the gap tripled to `3g`. Only once those three deeper recursions return does the function perform a gapped insertion sort of the current range at the *current*, smaller gap `g`. The recursion bottoms out once the gap grows larger than the remaining range, so gaps are implicitly generated in the sequence `..., 27, 9, 3, 1`, and passes are applied from the largest gap down to a final ordinary gap-1 insertion sort as the call stack unwinds.

Because each level triples the gap, the recursion is only `O(log₃ n)` deep, so the extra stack space it needs stays logarithmic in the array's size rather than growing with it. The three-way branching at each level also means every element participates in several gapped passes at different offsets before the plain insertion sort finishes the job, giving the same shrinking-gap behavior as the iterative algorithm while deriving the sequence structurally from the recursion itself rather than from a lookup table.
