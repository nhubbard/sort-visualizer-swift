*From Wikipedia, the free encyclopedia*

In-Place Merge Sort is a variant of [Merge Sort](https://en.wikipedia.org/wiki/Merge_sort) that sorts an array using only a constant (or logarithmic, accounting for recursion) amount of extra memory, rather than the O(n) auxiliary buffer that ordinary Merge Sort requires to combine two sorted runs. It keeps Merge Sort's [divide-and-conquer](https://en.wikipedia.org/wiki/Divide-and-conquer_algorithm) structure — recursively sorting the left and right halves of a range before combining them — but replaces the classic "copy both runs into a temporary array and write them back in order" merge step with one that rearranges elements directly within the array itself.

One common way to merge in place is by repeatedly swapping and shifting: whenever an element in the left run is found to be out of order relative to the right run, it is exchanged with an element from the right run, and the newly displaced value is then shifted — one adjacent swap at a time — into its correct position among the remaining elements. This avoids ever allocating a second array, but it means a single merge can require far more element movement than the simple linear scan-and-copy used by standard Merge Sort.

That extra movement is the central tradeoff: standard Merge Sort's merge step is O(n) per level because it only ever reads each element once when copying it into the temporary buffer. An in-place merge built from swaps and shifts can end up re-examining and re-positioning many elements per merge, which pushes the algorithm's overall running time toward the quadratic end of the scale in the average and worst cases, even though the recursive split still happens at every doubling of the array's size. Whether an in-place merge remains stable also depends heavily on the specific technique used — some in-place merge algorithms preserve the relative order of equal elements, while others, including simple swap-and-shift approaches, can allow equal elements to cross one another across separate merge calls.

In-Place Merge Sort is mostly of academic and pedagogical interest: it demonstrates that Merge Sort's memory requirement is not strictly unavoidable, but the techniques that remove it tend to cost enough in comparisons and data movement that, in practice, ordinary Merge Sort (with its O(n) buffer) or an in-place algorithm designed for speed from the outset, such as Quick Sort or Heap Sort, is usually preferred.
