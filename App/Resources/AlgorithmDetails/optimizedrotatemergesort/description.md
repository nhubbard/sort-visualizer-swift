Optimized Rotate Merge Sort is a stable [merge sort](https://en.wikipedia.org/wiki/Merge_sort) that combines short insertion-sorted runs with bounded temporary storage and in-place rotations. It first sorts consecutive runs of up to 32 elements. It then repeatedly merges adjacent runs while doubling the run length.

When a merge fits the temporary buffer, the algorithm copies values into that buffer and merges them back in order. Larger merges split one run near its midpoint, find the corresponding position in the other run by binary search, rotate the two crossing blocks, and continue on the resulting subproblems. The buffer has a fixed maximum size, so the additional storage does not grow with the input length apart from the recursion stack.

Equal values retain their original order. Insertion shifts only values greater than the element being inserted, buffered merges take an element from the left run first on a tie, and the two binary searches place equal values on the side that preserves their order during rotation. The initial runs take linear time because their length is fixed. The merge passes take O(n log n) time on typical inputs; the recursive rotation path can take O(n log² n) time in the worst case.
