*From Wikipedia, the free encyclopedia*

[Shellsort](https://en.wikipedia.org/wiki/Shellsort) sorts an array by performing multiple passes of an insertion-sort-like comparison, each pass working on pairs of elements a fixed distance ("gap") apart, with the gap shrinking from pass to pass down to 1. V. Pratt showed that if the sequence of gaps is chosen to be every "3-smooth" number — every integer of the form `2^a * 3^b` for non-negative `a` and `b` — visited in decreasing order, then a single comparison-and-swap pass at each gap is already enough to fully sort *any* input. That guarantee turns the technique into a genuine sorting network: a fixed, data-independent sequence of compare-and-swap operations, not a heuristic that merely tends to work well in practice.

This recursive variant reaches Pratt's exact gap set without ever computing a single gap value up front. Its sibling `ClassicThreeSmoothCombSort` tests every integer from `n` down to `1` for 3-smoothness directly, and its other sibling `ThreeSmoothCombSortIterative` walks nested loops over powers of 2 and 3 to build the same list. This variant instead uses two mutually structured recursive helpers: `recursiveComb(pos, gap, end)` recurses twice with `gap` doubled — once at the same starting position, once shifted forward by the current gap — covering every power-of-2 multiple of that gap across the whole array, and only after both of those calls return does it hand off to `powerOfThree(pos, gap, end)` at its own, undoubled gap. `powerOfThree` in turn recurses three ways with `gap` tripled, covering every power-of-3 multiple on top of that, and only after all three of those return does it perform the actual compare-and-swap pass, stepping through the array by its own gap. Because each level's recursive calls happen before that level's own pass, the largest gaps get their single pass first and the gaps shrink pass by pass afterward — exactly the decreasing-gap order Pratt's theorem requires — even though no part of the algorithm ever names a gap value directly; the full 3-smooth sequence simply falls out of how deep the doubling and tripling recursion happens to go.

Because Pratt's sequence sorts completely regardless of the input's arrangement, this algorithm's running time is identical in the best, average, and worst cases: Θ(n log²n). Where it genuinely differs from its two siblings is in space. `ClassicThreeSmoothCombSort` and `ThreeSmoothCombSortIterative` both drive the same gap sequence from a flat loop, so they need only O(1) auxiliary space beyond the array itself. This variant is truly recursive — there is no explicit loop over gap values anywhere in it — so it pays for a genuine call stack: the doubling recursion in `recursiveComb` can only run for O(log n) levels before its position-plus-gap bound exceeds the array's length, and within each of those levels the tripling recursion in `powerOfThree` can likewise only run for O(log n) further levels before hitting the same kind of bound. The deepest possible chain of live recursive calls, and therefore this algorithm's true auxiliary space cost, is O(log n).

This algorithm is not a [stable sort](https://en.wikipedia.org/wiki/Sorting_algorithm#Stability). A pass at gap `g > 1` compares and swaps elements that sit `g` positions apart, not neighbors, so two equal-valued elements that happen to lie between such a pair can be carried past one another by that pair's swap without the two equal elements ever being directly compared. Nothing in a later, smaller-gap pass is guaranteed to undo that crossing, so equal elements can and empirically do end up reordered relative to their original positions in the input.
