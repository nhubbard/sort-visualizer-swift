Complete Graph Sort is a sorting network: unlike a normal comparison sort, the sequence of index pairs it compares is fixed in advance and does not depend on the data at all. Every element still ends up compared against every other element by the end of the run — as if the array were a complete graph with an edge between each pair of positions — but which edges fire at which point is decided purely by arithmetic on the array's length, not by anything read out of the array itself.

The work is organized around a doubling "stride" that starts at 2 and keeps doubling until it passes the array's size. At each stride, the array is walked left to right and cut into small runs, and each run is handed to a `split` step that treats it as two adjacent halves meeting at a midpoint. `split` compare-swaps every element in the left half against every element in the right half, distributing the comparisons evenly across the run (including a bit of extra bookkeeping when the run has an odd length, so the leftover element still gets compared against everything on the other side). As the stride grows, the runs handed to `split` grow with it, so later passes make longer-range compare-swaps between elements that started out far apart, while earlier passes cleaned up short-range disorder.

Because the comparisons happen between positions that are not generally adjacent, and which positions get compared is fixed by the network rather than by the current contents of the array, a compare-swap late in the run can move one of two equal elements past the other without ever comparing it against the elements in between. Complete Graph Sort is therefore not a stable sort — equal elements can end up in a different relative order than they started in.

Its only means of making progress is exchanging pairs of elements found to be out of order — no inserting, selecting, or merging step is involved anywhere in the algorithm.
