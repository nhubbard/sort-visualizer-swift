Asynchronous Sort isn't heap-based either, despite sitting among the heap variants — it's a counting-style sort built around a rising threshold instead of comparisons. It copies the array, finds the minimum and maximum values present, and then sweeps a threshold upward one integer at a time starting from the minimum: on each sweep, every remaining copied value that's no greater than the current threshold gets written into the next output slot and marked as used, and the threshold only advances once every value at or below it has been placed.

Because the threshold is guaranteed to reach the true maximum eventually, and every value is guaranteed to be at or below that maximum, this always finishes — the number of sweeps needed depends on the spread between the smallest and largest value, not on how many elements there are, which is what makes it behave more like Counting Sort than like anything heap-shaped. It never compares two elements against each other directly; every decision is "is this value small enough for the current threshold yet," checked against a plain number.
